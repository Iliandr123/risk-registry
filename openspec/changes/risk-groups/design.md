# Дизайн групп рисков

## Context

Карточка риска состоит из опубликованной версии и полей уровня риска. Назначение ответственного уже меняется отдельной операцией под блокировкой строки риска. Next.js загружает данные списков на сервере, а текущие фильтры передаёт в URL.

## Goals / Non-Goals

**Цели.** Поддержать необязательную группу, немедленную смену опубликованной группы, устойчивые ссылки с фильтром и историю названий на момент действия.

**Границы.** Работа ведётся в рабочем реестре одной команды. Жизненный цикл группы включает создание и переименование. Учебный прототип остаётся автономным.

## Decisions

### Справочник и два этапа назначения

- Добавить справочник PostgreSQL со стабильным UUID, названием и ограничением уникальности нормализованного названия без учёта регистра. Сервер обрезает пробелы и проверяет зарезервированное название «Без группы». Ограничение в базе защищает от одновременного создания или переименования в одно имя.
- Первое предложение хранит необязательный выбор группы в строке версии. При первом утверждении сервер в той же транзакции переносит выбор в строку риска. После публикации текущая группа и её ревизия принадлежат риску. Обычная правка не записывает группу в опубликованный риск. Хранение текущей группы только в версии потребовало бы выпуска версии при каждом переносе и связало бы перенос с незавершёнными правками.
- Отсутствие группы хранится как `NULL`. Интерфейс отображает его словом «Без группы». Системная строка справочника потребовала бы исключений для переименования и обработки существующих записей.

### HTTP-контракт

- `GET /risk-groups` возвращает группы как `{id, name}` для активных участников. `POST /admin/risk-groups` и `PATCH /admin/risk-groups/{id}` принимают `{name}` и возвращают сохранённую группу. Использовать действующие правила рабочей сессии, проверки роли и CSRF. Повтор названия возвращает конфликт с пояснением для формы.
- В создание и сохранение первого предложения добавить необязательный `groupId`. При частичном сохранении отсутствие поля сохраняет текущий выбор, а `null` снимает его. Проверить существование указанной группы и ограничить изменение поля первым предложением.
- `PATCH /risks/{id}/group` принимает `{groupId, expectedGroupRevision}` и возвращает обновлённую опубликованную карточку. `groupId: null` снимает группу. Карточка содержит текущую группу или `null` и `groupRevision`, сводка списка содержит группу или `null`. Записывать перенос под существующей блокировкой риска, проверяя права, опубликованность, активное состояние и ревизию. Совпадение ID при актуальной ревизии возвращает текущую карточку без изменения ревизии.
- `GET /risks` для активного списка и архива принимает `group` со стабильным ID или значением `ungrouped`. Отсутствие параметра означает «Все группы». Сервер объединяет этот предикат поиска с действующими фильтрами. Ответ остаётся списком, что позволяет использовать его для секций активных рисков и единой таблицы архива.

### История и интерфейс

- В существующем событии первого утверждения фиксировать название группы как `initialGroupName`. У новой первой публикации без группы поле содержит `null`. У прежних событий и последующих утверждений поле отсутствует. Перенос создаёт общее событие `GROUP_CHANGED` с инициатором, временем и полями `previousGroupName` и `newGroupName`, которые допускают `null`.
- Сохранять строки названий в событии вместе с изменением риска в одной транзакции. При чтении названий для записи истории удерживать блокировки строк соответствующих групп до фиксации, захватывая несколько строк по порядку ID. Так запись истории согласуется с сохранением переименования. Вычисление исторических названий по текущему справочнику меняло бы уже опубликованные события.
- Добавить серверную загрузку справочника для админки, форм и фильтров. Группировать отфильтрованные строки активного списка по ID, сортировать заголовки по русскому алфавиту и переиспользовать таблицу. Для архива добавить колонку «Группа». Перенос обновляет данные карточки, истории и списка.

## Risks / Trade-offs

- Перенос может совпасть с утверждением завершения. Оба действия используют одну блокировку риска. После завершения перенос отклоняется, а при обратном порядке архивная карточка показывает сохранённую группу.
- Переименование меняет заголовок секции, поэтому фильтр и ссылки из списка хранят ID. История сохраняет названия на момент действия.

## Migration Plan

Создать резервную копию перед обновлением. Применить миграцию Liquibase при запуске новой версии API и развернуть клиент с обновлённым контрактом. Существующие риски и черновики получат пустую группу, события сохранят прежнее содержание. Для отката сохранить отдельную копию базы после обновления, восстановить базу из копии до миграции и развернуть предыдущие версии сервисов. Старый API не распознаёт события `GROUP_CHANGED`.
