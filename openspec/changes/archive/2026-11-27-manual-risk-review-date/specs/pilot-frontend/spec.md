# Ручная дата пересмотра в интерфейсе пилота

## MODIFIED Requirements

### Requirement: Серверный интерфейс пилота

Рабочий веб-интерфейс MUST использовать Next.js App Router в серверном режиме Node.js. Код фронтенда и его автоматических тестов MUST быть написан на TypeScript. URL раздела, фильтров и открытой карточки MUST поддерживать прямое открытие. Интерактивные компоненты MAY обновлять данные в браузере после действий.

#### Scenario: Серверная загрузка рабочего раздела

- **WHEN** участник с действующей сессией открывает рабочий URL
- **THEN** Next.js на сервере проверяет профиль через Java API и формирует HTML с доступными участнику данными раздела или карточки ещё до выполнения JavaScript
- **AND** поиск и фильтры опубликованных рисков передаются Java API

#### Scenario: Защита при прямом открытии

- **WHEN** раздел открывают без сессии, до смены временного пароля или без роли для раздела
- **THEN** сервер показывает форму входа, форму смены пароля или сообщение о недоступном разделе соответственно
- **AND** данные недоступного раздела не запрашиваются и не попадают в HTML

#### Scenario: Отображение дат

- **WHEN** участник открывает карточку с оценкой и историей или список активных рисков
- **THEN** интерфейс показывает дату оценки в карточке и действующий срок пересмотра активного риска в карточке и списке по данным API
- **AND** в карточке видно, когда срок задан вручную
- **AND** время событий отображается в UTC в начальном HTML и после загрузки JavaScript

#### Scenario: Обновление срока и отметки после действия

- **WHEN** участник сохраняет изменение, влияющее на срок, или ревьюер подтверждает оценку
- **THEN** карточка и список показывают актуальный срок и отметку «Требует пересмотра» без ручной перезагрузки страницы

#### Scenario: Подтверждение оценки с ручной датой

- **WHEN** ревьюер выбирает «Подтвердить оценку» у риска с ручным сроком
- **THEN** интерфейс показывает назначенную дату и запрашивает подтверждение её снятия
- **AND** при отмене подтверждения состояние риска сохраняется

#### Scenario: Учебная демонстрация

- **WHEN** участник открывает учебный прототип
- **THEN** прототип доступен как отдельный статический HTML

### Requirement: Два вида автоматических тестов

Автоматические тесты MUST ограничиваться компонентными проверками фронтенда с HTTP-заглушкой бэкенда и E2E с запущенным Spring Boot и отдельной PostgreSQL. Проверки типов, линтер, сборка и валидация схемы OpenAPI входят в технические проверки.

#### Scenario: Компонентный тест со сверкой контракта

- **WHEN** сценарий компонента выполняется с HTTP-заглушкой
- **THEN** проверяются серверный HTML или взаимодействие с реальным компонентом, операция OpenAPI, параметры, CSRF при записи, тело запроса, статус и схема ответа заглушки
- **AND** тест падает при неожиданном запросе или нарушении схемы

#### Scenario: Полный сценарий на реальном API

- **WHEN** E2E открывает рабочий интерфейс с запущенными Next.js, Spring Boot и PostgreSQL
- **THEN** через браузер проверяются роли, смена временного пароля, создание, возврат и утверждение, конфликт ревизий, видимость публикации, подтверждение оценки и архив с историей
- **AND** проверяются прямое сохранение по ролям, немедленная видимость правки для команды, история значений до и после, конфликт сохранения со старой версии и сохранность свежих полей при завершении
- **AND** проверяются сохранение мер с ручной датой, сохранение даты при переоценке и возврат к автоматическому сроку после досрочного подтверждения
