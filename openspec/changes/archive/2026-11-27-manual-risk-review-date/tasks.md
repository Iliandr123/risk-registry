# Задачи по ручной дате пересмотра

## 1. HTTP-контракт

- [x] 1.1 Обновить `api/openapi.yml` для PATCH опубликованного риска, данных оценки и записей истории. Описать пропуск, сброс, дату и проверку исходного значения. Перегенерировать типы фронтенда и выполнить `npm run api:check`.

## 2. Данные и API

- [x] 2.1 Добавить миграцию Liquibase для ручной даты и истории. Проверить, что у риска, созданного до миграции, действует прежний автоматический срок, а существующие события читаются после миграции.
- [x] 2.2 Добавить сохранение даты с прямой правкой и вычисление действующего срока для карточки и списка. В E2E с реальным API проверить дату сегодня, будущую дату позже квартала, отказ для неверной и прошлой новой даты, сохранение просроченного значения при правке мер, сброс к уже просроченному автоматическому сроку и отсутствие нового события при сохранении тех же значений.
- [x] 2.3 Реализовать снятие даты при подтверждении и историю обоих действий. В E2E проверить сохранение ручной даты при изменении баллов, досрочное подтверждение, историю, права на правку и подтверждение, отклонение для неопубликованного и архивного риска и обе последовательности конкурентных записи даты и подтверждения.

## 3. Интерфейс рабочего пилота

- [x] 3.1 Добавить поле даты в редактор, отображение источника срока в карточке и историю ручной даты. Компонентными тестами проверить запросы установки и сброса, отображение карточки и списка и сверку значения после конфликта.
- [x] 3.2 Добавить запрос подтверждения снятия ручной даты и обновление карточки, списка и истории после действий. Компонентными тестами проверить отмену без запроса, показ снимаемой даты и обновление срока и отметки. Приложить скриншоты формы и подтверждения.
