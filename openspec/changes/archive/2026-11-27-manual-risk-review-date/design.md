# Дизайн ручной даты пересмотра

## Context

Spring Boot вычисляет `reviewDueDate` и `reviewRequired` для карточки и списка от даты оценки. Прямая правка проверяет ожидаемую опубликованную версию и записывает изменения полей в историю. Подтверждение оценки использует текущий снимок и обновляет дату оценки на самом риске.

## Goals / Non-Goals

Ручной срок используется во всех представлениях рабочего реестра. Назначение срока и правка полей сохраняются одним действием. План охватывает активные опубликованные риски рабочего пилота, а также показ их истории после архивирования.

## Decisions

### Действующий срок рассчитывает сервер

- Добавить nullable-колонку PostgreSQL типа `date` для ручной даты на записи риска. Дата действует до явного сброса или подтверждения оценки. Дата оценки и ручная дата хранятся раздельно, поэтому можно изменить оценку и сохранить назначенный пересмотр.
- Возвращать `manualReviewDate` в объекте `assessment` карточки и списка. `reviewDueDate` содержит ручную дату при её наличии или дату оценки плюс три календарных месяца. `reviewRequired` вычисляется по действующему сроку и текущей дате команды.

### Одно сохранение для содержания и срока

- Расширить существующий PATCH необязательным верхнеуровневым `manualReviewDate`. Пропуск сохраняет текущую настройку, `null` сбрасывает её, строка `YYYY-MM-DD` устанавливает дату. Если поле передано, запрос также передаёт `expectedManualReviewDate` из исходной карточки, включая `null` для автоматического режима. Запросы без обоих полей сохраняют прежнюю семантику.
- Под блокировкой риска проверить права, активное состояние, ожидаемую опубликованную версию и ожидаемую ручную дату, когда она передана для изменения. Для нового значения проверить формат, календарную корректность и нижнюю границу по дате команды. Уже сохранённое значение может оставаться просроченным при правке других полей. Несовпадение исходной даты возвращает существующий конфликт риска.
- Изменение даты, в том числе сохранённое отдельно от остальных полей, создаёт новую опубликованную версию и одно событие `FIELDS_UPDATED`. Событие хранит прежнее и новое ручные значения на момент записи. Использовать их вместе с разницей снимков, чтобы показать один список изменённых полей. Отдельная версия позволяет существующей проверке отклонить подтверждение, открытое до изменения даты.

### Явное подтверждение снимает дату

- В существующей транзакции подтверждения оценки сбросить ручную дату, обновить дату оценки и записать снятую дату в событие `CONFIRM_ASSESSMENT`. События прошлых подтверждений доступны без этого значения. У подтверждения сохраняются действующие права ревьюера и проверка опубликованной версии.
- Форма прямой правки хранит исходную ручную дату и значение пользователя. При конфликте сверка показывает оба варианта и позволяет взять текущий. При ручном сроке действие «Подтвердить оценку» сначала предлагает подтвердить снятие показанной даты. После успешной записи обновить карточку, список и историю через существующие механизмы загрузки.

## Risks / Trade-offs

- Подтверждение может снять дату без смены опубликованной версии. Сверка ожидаемой ручной даты защищает от сохранения устаревшего значения, а новая версия при назначении даты защищает от подтверждения по устаревшей карточке.
- Локальная дата браузера может отличаться от даты команды. Передавать календарную дату без смещения и проверять её допустимость на сервере.

## Migration Plan

Внести добавочную миграцию Liquibase для колонки риска и значений истории. Для существующих рисков и событий оставить новые колонки пустыми, чтобы сохранились прежние сроки и история. При откате приложения сохранить добавленные колонки и данные. Предыдущая версия приложения будет применять автоматический срок.
