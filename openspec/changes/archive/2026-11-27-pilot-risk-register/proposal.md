# Пилот командного реестра рисков

## Согласование

Владелец проекта согласовал требования, технический дизайн и план задач пилота. Старт реализации отложен до отдельного запроса владельца проекта.

## Why

Владелец проекта принял автономный прототип. Пилот проверит, может ли команда провести реальный продуктовый риск через ревью и зафиксировать решение в общем реестре, который останется доступен после рабочей встречи.

## What Changes

- Запустить рабочий реестр для одной команды с локальными учётными записями, администрированием через интерфейс и общим хранением данных.
- Перенести полный цикл риска из демонстрации. Добавить отзыв и закрытие первого предложения, разблокировку зависшей правки и проверку доступности владельца при одобрении.
- Вести общий HTTP-контракт в `api/openapi.yml` и обновлять его до реализации изменений API.
- Подготовить внутреннее развёртывание, резервное копирование, сверку доступа после восстановления и проведение одной рабочей встречи.
- Сохранить автономную демонстрацию. Пилот начинает работу с пустым реестром. Мониторинг доступности, корпоративный вход и почтовые интеграции вне объёма.

## Capabilities

### New Capabilities

- `team-accounts`: локальный вход, управление участниками и отзыв сессий.

### Modified Capabilities

- `risk-register`: рабочий реестр с полным циклом риска и серверным контролем доступа в дополнение к автономной демонстрации.

## Impact

Рабочий интерфейс в Next.js, API на Java 25, PostgreSQL и запуск через Docker Compose. До запуска с командой требуется короткий самостоятельный прогон прототипа коллегами. Один назначенный ответственный ведёт стенд и процесс.
