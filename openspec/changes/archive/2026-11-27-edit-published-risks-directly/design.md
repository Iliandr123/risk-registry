# Дизайн прямого редактирования рисков

## Context

Сейчас рабочий реестр публикует снимок карточки при утверждении предложения. Предложение обычной правки и предложение о завершении проходят через один черновик. Назначение, группа и случаи проявления хранятся отдельно от снимка риска. Дата оценки хранится у риска, а бэкенд возвращает рассчитанный срок пересмотра.

## Goals / Non-Goals

- Сохранить опубликованные снимки неизменяемыми и фиксировать автора прямой правки, привязанный к ней снимок и её исходную версию одной транзакцией.
- Сохранить идентификатор риска, раздельные права на назначение и группу, текущий процесс первой публикации и согласования завершения. Ручной ввод срока относится к будущему изменению.

## Decisions

### Контракт сохранения и права

Добавить `PATCH /risks/{id}` с `expectedPublishedVersionId` и объектом `fields`. Объект принимает только восемь полей, перечисленных в дельте реестра. Пропущенное поле сохраняет значение, `null` очищает заметку или ссылку. После наложения полей сервер проверяет заполненность и допустимость всей карточки. Успешный ответ возвращает актуальный `PublishedRisk`.

Под общей блокировкой строки риска проверить наличие публикации, активное состояние, текущего ответственного и исходную версию. Использовать действующие механизмы сессии и CSRF. Для неопубликованного или отсутствующего риска возвращать `404`, для недостаточных прав — `403`, для архивного риска или устаревшей версии — `409`, для недопустимых полей — `400`. Запрос без фактических изменений с актуальной версии возвращает текущую карточку.

Форма открывается на месте действия «Предложить правку». После успешного сохранения обновить карточку, историю и текущий список с сохранением выбранных фильтров. При конфликте загрузить свежий снимок без перемонтирования формы, показать введённые и текущие значения и предложить пользователю выбрать итоговые значения перед отправкой с новым ID версии. Если риск уже архивирован или право отозвано, повторное сохранение недоступно.

### Снимки и общая история

Записывать новый снимок, указатель текущей версии и публичное событие `FIELDS_UPDATED` в одной транзакции. Хранить у события идентификатор исходного опубликованного снимка и ссылку на новый. Это позволяет сопоставить точные значения двух версий, даже если между их публикациями были события назначения, смены группы или подтверждения оценки.

В `GET /risks/{id}/history` возвращать для события массив `changes` с ключом поля, прежним и новым значением. Значения остаются строками, целыми числами или `null` в соответствии с полем. Интерфейс подписывает поля и показывает «Не указано» для пустого необязательного значения. Исторические записи прежнего процесса используются в существующем виде.

### Дата оценки и срок пересмотра

При изменении оценки взять текущую календарную дату команды из общего календаря риска. При правке остальных полей использовать дату оценки, прочитанную под блокировкой, включая подтверждение ревьюером, состоявшееся после открытия формы. Оставить единый расчёт `reviewDueDate` и отметки о пересмотре для списка и карточки. Расчёт принимает дату оценки, применяет `plusMonths(3)` и использует действующую календарную зону команды для сравнения с текущим днём. Позднее ручной срок можно будет подключить как вход этого расчёта с прежним ответом API.

### Отдельное предложение о завершении

Переиспользовать существующие переходы черновика, отправки, возврата, отзыва, закрытия и утверждения для отдельной формы «Завершить риск». Для новых предложений после публикации разрешить только состояние «Снят» или «Реализовался» и причину. Проверять обязательную причину при отправке. При утверждении под блокировкой собрать архивный снимок из последних опубликованных полей, статуса и причины предложения, сохранив актуальные назначения, группу, оценку и случаи проявления. Если прямое сохранение получило блокировку первым, его результат попадёт в архив. Если первым утверждено завершение, прямое сохранение отклоняется.

## Risks / Trade-offs

- Устаревшая вкладка может вызвать старый HTTP-оператор предложения правки. Сервер отвергает создание обычной правки и изменение полей через процесс завершения.
- Черновики могут содержать приватные данные. Проверять доступ к содержимому и событию закрытия по исходному авторству и факту прежней отправки.
- Изменение `risk-groups` уже реализовано и пока находится в отдельной дельте. Требование «Общий реестр команды» включает его сценарии, чтобы последующее архивирование сохранило группировку. Перед архивированием этого изменения первым архивировать `risk-groups` и сверить его сценарии о смене группы при открытом предложении о завершении.

## Migration Plan

1. Миграцией Liquibase закрыть открытые обычные правки опубликованных рисков. Считать обычными правками записи с состоянием «Активен». Записать системное событие с пояснением о переходе на прямое редактирование. Оставить поля версии, автора и прежнюю видимость. Отдавать содержимое закрытой правки авторизованным участникам через историю, включая доступ для автора приватного черновика.
2. Сохранить открытые предложения со статусом завершения и их состояние ревью. Показывать их через отдельную форму. При утверждении брать из предложения только статус и причину.
3. Проверить обновление на копии базы со старыми предложениями перед развёртыванием. Для восстановления до миграции использовать предрелизную копию базы и соответствующую версию приложения.
