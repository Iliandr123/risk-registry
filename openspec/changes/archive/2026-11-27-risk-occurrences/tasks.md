# Задачи по случаям проявления риска

Сценарии приёмки описаны в [дельте требований](specs/risk-register/spec.md), технические решения — в [дизайне](design.md).

## 1. HTTP-контракт

- [x] 1.1 Добавить операции списка, создания, исправления и удаления в `api/openapi.yml` до изменения сервера и клиента. Описать формы записей, курсор, ревизию, права, CSRF и ответы ошибок. Выполнить `python -m openapi_spec_validator api/openapi.yml` из корня, затем `npm run api:generate` и `npm run api:check` из `frontend/`.

## 2. Данные и сервер

- [x] 2.1 Добавить миграцию Liquibase и хранение случаев по ID риска. Проверить запуск на пустой базе и обновление существующей базы. После перезапуска проверить сохранность добавленных случаев и данных ранее опубликованных рисков.
- [x] 2.2 Реализовать чтение и создание. В E2E с реальным API проверить сохранение текста, ссылки и обоих полей, допуск повторов, отказ для пустого ввода и недопустимого URL, видимость записи другому активному участнику, пагинацию через границу 20 записей и отказ в чтении и создании у неопубликованного риска.
- [x] 2.3 Реализовать исправление и удаление с проверкой прав, состояния риска и ревизии. В E2E проверить автора записи, ревьюера, администратора без роли ревьюера, запрет для другого участника и для ID случая из другого риска, отклонение запроса без CSRF, конфликт устаревшего изменения и отсутствие событий исправления и удаления в истории.

## 3. Карточка

- [x] 3.1 Добавить серверную загрузку первой страницы и карточку списка с загрузкой следующих страниц, временем в UTC и кликабельными ссылками. В компонентных тестах с валидирующей HTTP-заглушкой проверить начальный HTML и запрос следующей страницы.
- [x] 3.2 Добавить формы записи и исправления, подтверждение удаления и обработку ошибок. В компонентных тестах проверить доступность действий по роли и состоянию риска, три допустимых варианта заполнения, сохранение ввода при ошибке, обновление списка и предложение обновить карточку при конфликте. Приложить скриншоты активной и архивной карточек.

## 4. Интеграция

- [x] 4.1 В E2E проверить доступность случаев при открытой правке и согласовании завершения, сохранение списка после публикации новой версии, сохранение статуса, приоритета и дат при добавлении случая. Проверить просмотр в архиве, запрет всех трёх операций записи после архивирования и возможность завершить риск с пустым списком.
- [x] 4.2 На Node.js 24 запустить `npm run lint`, `npm run typecheck`, `npm run build`, `npm run test:components` и `npm run test:e2e` из `frontend/`. Для E2E использовать Spring Boot и отдельную PostgreSQL. Собрать бэкенд командой `./gradlew.bat build` на JDK 25. Зафиксировать результаты и оставить задачи с непрошедшими обязательными проверками открытыми.

## Результаты проверок

- Node.js 24.20.0. Линтер, проверка типов и соответствия типов OpenAPI, production-сборка и компонентный набор прошли.
- E2E на отдельном стенде `pilot-e2e` со Spring Boot и PostgreSQL 17. Браузерный сценарий пилота и серверные сценарии назначения и случаев прошли.
- JDK 25.0.5.1. Сборка бэкенда через `./gradlew.bat build` прошла.
