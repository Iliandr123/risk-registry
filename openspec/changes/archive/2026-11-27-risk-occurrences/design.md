# Дизайн случаев проявления риска

## Context

Рабочий реестр сохраняет опубликованные версии по постоянному идентификатору риска. Опубликованную карточку и историю Next.js загружает через Spring Boot API. Запись назначения и утверждение завершения уже используют блокировку строки риска.

## Goals / Non-Goals

Первая страница случаев должна быть доступна в серверном HTML. Количество случаев может расти независимо от объёма карточки и истории. Изменение охватывает опубликованную карточку рабочего реестра. Общая таблица, автономный прототип и интеграции с внешними страницами находятся за границами задачи.

## Decisions

- **Хранение.** Добавить таблицу PostgreSQL с идентификатором записи, внешними ключами на риск и автора, временем создания, текстом, URL и ревизией. Привязка к риску сохраняет записи при смене опубликованной версии. Автор и время создания фиксируются при добавлении. Удаление удаляет строку. Для чтения добавить индекс по риску, времени создания и идентификатору записи.
- **Контракт.** Добавить `GET` и `POST` на `/risks/{id}/occurrences`, `PATCH` и `DELETE` на `/risks/{id}/occurrences/{occurrenceId}` с тегом «Риски». `GET` возвращает до 20 записей по убыванию времени создания и ID, а также непрозрачный курсор следующей страницы. Запись в ответе содержит ID, текст, URL, автора, время создания и ревизию. `POST` возвращает запись с `201`. `PATCH` принимает текст, URL и `expectedRevision`, возвращает обновлённую запись с `200`. `DELETE` принимает `expectedRevision` в параметре запроса и возвращает `204`.
- **Проверка запросов.** Существующие правила сессии и CSRF распространяются на новые маршруты. Сервер ищет запись по ID риска и случая. Отсутствующая запись или неопубликованный риск дают `404`, нехватка прав на изменение чужой записи даёт `403`. Проверка активного состояния и ревизии выполняется в транзакции под блокировкой строки риска, общей с утверждением завершения. Архивное состояние при записи или устаревшая ревизия дают `409 RISK_CONFLICT`. Ошибочный курсор, пустая запись или недопустимый URL дают `400`.
- **Карточка.** После подтверждения доступности опубликованной карточки Next.js загружает первую страницу через существующий API-клиент. Показывать текст как обычный текст, ссылку как ссылку HTTP или HTTPS без предпросмотра. Во время отправки блокировать повторное нажатие. После успешной записи заново загрузить первую страницу. При конфликте предложить обновить карточку, при ошибке в полях сохранить ввод.

## Risks / Trade-offs

- Активный риск могут архивировать после открытия формы. Общая блокировка упорядочивает операции. Запись, сохранённая первой, видна в архиве. Действие, пришедшее после архивирования, отклоняется.
- Несколько записей могут иметь одинаковое время создания. Порядок по времени и ID сохраняет однозначную границу между страницами. Отдельная коллекция позволяет загружать случаи порциями независимо от истории риска.

## Migration Plan

Применить добавочную миграцию Liquibase при запуске API. У существующих рисков список пуст, перенос данных не требуется. Выпустить совместимые версии API и фронтенда. При откате вернуть совместимую пару прежних приложений и сохранить добавленную таблицу с данными.
