# Проверка автономного прототипа

Открыть `../public/risk-register.prototype.html` двойным щелчком. Установка зависимостей и сервер не нужны. Все данные и заметки хранятся в памяти страницы и сбрасываются при обновлении.

Из `frontend/` запустить поведенческие проверки встроенным раннером Node.js (20.9+):

```sh
node --test tests/risk-register.prototype.test.cjs
```

Тесты извлекают чистую модель непосредственно из HTML, без копии логики и дополнительных пакетов. Проверяются переходы, права, видимость, сохранение опубликованных версий, завершение, оценки и календарные даты.

Для ручной проверки пройти шесть сценариев кнопками в верхней панели. Каждый сценарий восстанавливает исходные данные. Затем в свободном режиме проверить ввод, поиск, фильтры, переключение участников и раскрытие истории. При переключении участника несохранённые поля теряются: сначала сохранить черновик.

При проверке с командой записать затруднения в поле наблюдений и скопировать их перед закрытием. Оценка понятности настоящими участниками и совместный пилот остаются отдельным этапом.

Те же шесть пошаговых сценариев можно прогнать в Chrome с отключённой сетью.

```sh
node --test tests/prototype.browser.test.mjs
```

## Рабочий пилот

Запустите API с отдельной тестовой PostgreSQL и интерфейс Next.js. Браузерный и контрактный тесты создают участников и риски в этой базе. Для обоих задайте `PILOT_ADMIN_LOGIN` и `PILOT_ADMIN_PASSWORD` для тестового администратора. Если у него ещё временный пароль, запустите сначала браузерный тест с `PILOT_NEW_ADMIN_PASSWORD`, а затем используйте новый пароль в контрактном тесте.

Из `frontend/` запустите браузерную проверку. По умолчанию используются установленный Chrome и `http://localhost:3000`. Канал браузера можно задать переменной `PILOT_BROWSER`, например `msedge`, а адрес интерфейса — через `PILOT_UI_URL`. Чтобы сохранить снимок таблицы, задайте путь в `PILOT_SCREENSHOT`.

```sh
node --test tests/pilot.browser.test.mjs
```

Из корня репозитория запустите проверку HTTP-ответов по схемам `api/openapi.yml`. По умолчанию тест обращается к `http://localhost:8080/api`. Другой адрес задаётся в `PILOT_API_URL` с суффиксом `/api`.

```sh
python -m pip install openapi-spec-validator==0.7.2
python api/pilot_contract_test.py -v
```
