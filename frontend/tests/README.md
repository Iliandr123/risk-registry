# Проверки рабочего пилота

Тесты написаны на TypeScript и запускаются из `frontend/` на Node.js 24 после `npm ci`. Нужен установленный Chrome. Для другого установленного канала Chromium задайте `PILOT_BROWSER`, например `msedge`.

## Компоненты с контрактом OpenAPI

```sh
npm run test:components
```

Команда собирает и запускает Next.js и отдельную HTTP-заглушку на локальных портах. Заглушка сверяет запросы и ответы сценариев с [OpenAPI](../../api/openapi.yml), а тесты проверяют HTML и поведение реальных React-компонентов в браузере. Spring Boot и PostgreSQL для этого набора не нужны.

## E2E с настоящим API

Поднимите отдельный стенд с PostgreSQL и Spring Boot. Чтобы не использовать том рабочего пилота, выполните из корня проекта:

```sh
docker compose -p pilot-e2e up --build --wait
docker compose -p pilot-e2e run --rm backend bootstrap-admin operator "Администратор E2E"
```

Если порт уже занят, задайте для Compose другой `PILOT_PORT`. Укажите `PILOT_UI_URL` с соответствующим адресом `http://localhost:<порт>`. По умолчанию тест использует `http://localhost:3000`.

Задайте `PILOT_ADMIN_LOGIN` и `PILOT_ADMIN_PASSWORD` для отдельного тестового администратора. Если пароль временный, задайте также `PILOT_NEW_ADMIN_PASSWORD`. При повторном запуске используйте уже изменённый пароль в `PILOT_ADMIN_PASSWORD` и удалите `PILOT_NEW_ADMIN_PASSWORD`. Тест создаёт участников и риск в указанной базе.

```sh
npm run test:e2e
```

Серверные сценарии можно запустить отдельно командами `npm run test:e2e:assignment`,
`npm run test:e2e:occurrences` и `npm run test:e2e:groups`.
Для прямого подключения к Spring Boot задайте `PILOT_API_URL` и укажите действующий
постоянный пароль тестового администратора без роли ревьюера в `PILOT_ADMIN_PASSWORD`.

Для остановки выполните из корня `docker compose -p pilot-e2e down`. Том с тестовыми записями сохраняется.

## Ручная приёмка учебного прототипа

Откройте [автономный HTML](../public/risk-register.prototype.html) двойным щелчком. Данные хранятся в памяти и сбрасываются при обновлении. До командного пилота автор и ревьюер самостоятельно проходят свои сценарии и объясняют приоритет риска и различие между предложением и опубликованной версией. В поле наблюдений можно сохранить замечания и скопировать их перед закрытием.
